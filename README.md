# Tera

> *Tera* (Indonesian): to officially calibrate a measuring instrument.

**Tera calibrates your pricing.** Run a virtual customer through upgrades, trials, coupons, seats, metered usage and taxes, and see every invoice to the cent before a real customer does. The billing rules mirror Stripe, and each one is pinned down by hand-derived golden scenarios.

- **Live:** https://tera-orpin-three.vercel.app
- **API spec:** [`/api/openapi.json`](https://tera-orpin-three.vercel.app/api/openapi.json)
- **PRD:** [`docs/PRD.md`](docs/PRD.md) (billing rules R1–R9, invariants I1–I6)
- **Golden scenarios:** [`golden/scenarios.json`](golden/scenarios.json), 25 scenarios with expected invoices derived by hand and never generated by the engine

## What's inside

| Feature | Where |
|---|---|
| **Stripe parity: 22/22 golden scenarios replayed in Stripe test mode (test clocks) and matched line by line** | `/parity`, `scripts/verify-golden.mts`, evidence in `golden/parity/` |
| Customer timeline simulator | `/` |
| Price migration planner (MRR impact, grandfathering) | `/migrate` |
| Public API: `POST /api/simulate`, `POST /api/migrate`, `GET /api/scenarios[/:id]` | `src/app/api` |
| Pure, deterministic billing engine | `src/lib/billing.ts` |

## Tests: what a green check means

| Layer | What runs | When |
|---|---|---|
| Unit | The engine against all 25 golden scenarios, plus invariants (totals add up, integer money, determinism) | `npm test` |
| TestSprite API | `/api/simulate` against golden scenarios, plus validation errors (400/422/404) | Every PR, blocks merge |
| TestSprite UI | Load a scenario, edit the timeline, and assert exact invoice amounts and locale formatting | Every PR, blocks merge |

A green check means every golden invoice total still matches to the cent, in every currency, through the UI and the API.
